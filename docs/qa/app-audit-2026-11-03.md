# App audit — 3 November 2026

The original review below was read-only and records the pre-fix behavior of the
interactive Prototype, regression tests and live data routes. The resolution
section records the subsequent fixes authorized by the user. Source line
references in the original findings describe that audit snapshot.

## Findings

### P2 — Search and browsing history diverge

- Search a new query, open Recent, delete that visit through its menu, then open
  a new Search. The query remains in Search history even after its last browsing
  visit was removed. `BingAppPrototype.tsx:110` only updates `browsingHistory`.
- A Bing query followed from inside a SERP/IAB document is added to Recent but
  not to Search history. `LiveSERP.tsx:29` creates a document navigation, and
  `BingAppPrototype.tsx:124` records its page without updating `searchHistory`.
- Search-to-Recent removal and History's Clear all already synchronize the two
  collections. The missing reverse/update paths make the behavior inconsistent.
- Fix direction: derive the query view from the same visit collection, or update
  both collections consistently, preserving other visits to a repeated query and
  excluding private visits.

### P2 — Multi-card accepts a predominantly vertical drag as a horizontal swipe

- From slide 2, a pointer movement of −60 px horizontally and +150 px vertically
  moves the track from −330 to −390 and selects slide 3 on release.
- `FeedCard.tsx:373` checks direction only for pointer capture. The actual
  horizontal position is updated unconditionally, and release at line 404 only
  considers horizontal distance.
- An isolated component check reproduced this behavior. On touch, native
  scrolling can cancel the gesture before release, but horizontal displacement
  can still occur before cancellation. The desktop drag reproduces the page
  change directly.
- Fix direction: establish and retain the gesture direction before moving the
  carousel, retaining vertical scrolling and existing click suppression.

### P2 — Live AS never marks a previously searched query as history

- Search `weather`, return to Search and type it again. The matching live AS row
  still has the `Suggested query` image rather than `From search history`.
- Verified in the browser with both `weather` and `weather channel` already in
  the current session's Search history.
- `services/searchSuggestions.ts:28` assigns `prediction` to every response.
  `Search.tsx:76,182` renders that response without matching local history.
- The public API legitimately supplies predictions only; the app already owns
  the local history needed to mark matches. This is a remaining requirement gap
  from the two-source icon behavior, rather than a failure of the public API.
- Fix direction: mark applicable normal-mode AS matches from local history;
  private mode must continue excluding normal history. Missing logos remain
  omitted, since the current source supplies none.

### P3 — Keyboard editing of Search history loses focus

- Focus Edit search history with a physical keyboard and activate it with Enter.
  Focus falls to `document.body`, rather than the edit controls or first row.
  This was reproduced in the browser.
- `SearchHistory.tsx:79` makes the focused Edit control disabled/inert without
  transferring focus. Done has the reverse problem; removing a focused row also
  has no explicit next-target restoration at line 61.
- Pointer use usually retains the input focus because pointer-down is prevented,
  so this is chiefly a physical-keyboard/accessibility issue.
- Fix direction: transfer focus when the active control disappears, choosing the
  next row, Done or the search field as appropriate.

### P3 — News cannot be refreshed while retaining prototype activity

- `LiveHomepageFeed.tsx:57` requests the first page only on mount. Its minute
  timer at line 73 updates relative timestamps, not the articles.
- Returning Home or refocusing a long-running tab does not request a fresh first
  page, even after the server cache expires. New pagination still works.
- Refreshing the whole app obtains a fresh page but also resets session activity.
  A refresh policy or explicit refresh entry would improve long-running demos.

### P3 — Offscreen news images load eagerly

- The live first page currently returns 40 stories. All are rendered through
  `LiveHomepageFeed.tsx:89`, including stories far below the initial viewport.
- `FeedCard.tsx:193` does not use lazy loading. Additional feed pages accumulate
  more mounted image/card nodes.
- Fix direction: retain eager loading for visible art, defer offscreen images,
  and consider rendering-window limits if lengthy scrolling remains expensive.
  No measured frame-rate regression is claimed by this source inspection.

## Verification

- The local app and its main module return HTTP 200. Production build,
  TypeScript and design-token validation pass.
- Default `npm test`: 456/459 passed across 69 files. Three tests failed in
  parallel: Profile bookmark return timed out; SERP/Recent focus restoration
  timed out; the failed IAB request test did not observe its alert in time.
  Rerunning those three files with `--maxWorkers=1` passed all 21 tests. These
  results indicate timing instability under concurrent load; they do not prove
  an app failure for those three flows.
- Isolated multi-card reproduction: 1/1 checks passed while asserting the
  currently incorrect diagonal-drag behavior. This is evidence of a bug, not
  evidence of a fix.
- Isolated navigation reproductions: 3/3 checks confirmed deletion divergence,
  missing in-document queries in Search history and live AS source
  misclassification. These also assert the current incorrect behavior.
- Browser checks covered Home → Search → SERP → Recent, Recent filtering → AS
  → SERP → a fresh Recent, loaded tab previews, five live AS entries, history
  source icons and keyboard focus during history editing. The tested browser
  reported no error/warning logs.
- Live checks: MSN first page returned 40 stories with a next page; Bing results
  and AS returned successfully; three sampled MSN article previews returned
  successfully with matching titles. External content can change.
- Rewards remains a local captured snapshot. IAB is an HTML preview rather than
  a complete authenticated browser. Settings/Share/Feedback and other previously
  documented passive destinations were not misclassified as new regressions.
- Temporary reproduction scripts and logs remain under `/tmp`; no project
  dependencies or source tests were added.

## Resolution — 3 November 2026

All six findings have been addressed:

- Search and browsing history now synchronize in both directions. Deleting a
  query's final visit removes its Search entry; deleting one of several visits
  retains it. New in-document Bing queries enter Search history once, while
  Back/Forward cannot revive deleted visits. Private activity remains excluded.
  Query identity consistently folds whitespace and case; recorded URLs remain
  intact, including related-search links containing repeated whitespace.
- Feed Multi-card resolves gesture intent before moving horizontally and retains
  that direction for the full press. Vertical/diagonal feed gestures do not page
  or open articles; horizontal drags and interrupted spring settling still work.
- Search and Recent annotate the existing five live AS entries from exact local
  query matches. Normal history uses the history icon; private suggestions do
  not disclose it. Backend order and optional logos are preserved.
- Physical-keyboard editing transfers focus between Edit and Done. Deleting a
  focused row selects the next/previous surviving Remove control, and deleting
  the last row returns focus to the input. Pointer actions retain input focus.
- A first news page older than five minutes refreshes when Homepage becomes
  active/visible or returns to the top. Deep reading defers replacement, including
  a response arriving after the reader scrolls away. History, Tabs and scrollTop
  are retained. Refresh errors retain the old news and can be retried; refreshed
  pagination rejects stale observer callbacks/cursors.
- The lead news image loads eagerly; remaining article images are lazy and use
  asynchronous decoding, including inactive carousel slides.

Phone-prototype checks confirmed history deletion synchronization, five live AS
entries and history icons, private isolation, Edit/Done/final-row focus, vertical
diagonal versus horizontal carousel drags, and eager/lazy image attributes. The
browser reported no warning/error logs. Refresh aging, in-flight response staging,
retry and cursor replacement are covered by controlled-clock regression tests.
An actual aged homepage also refreshed successfully on returning to the top:
`data-fetched-at` advanced from `2026-11-03T06:03:54.187Z` to
`2026-11-03T06:12:51.678Z`, retaining both test tabs and the 40-story page.
The service tests are now included in the default Vitest discovery pattern.

Final validation: `npm test -- --maxWorkers=1` passed all 486 tests across 71
files. Production build (including TypeScript and token contracts) and
`git diff --check` passed. A prior concurrent run overlapped the final carousel/
feed regression edits and exposed an existing SERP test's premature focus check;
the fixed snapshot passed in full. That SERP test now waits for observable Search
exit/focus completion rather than treating an early iframe mount as completed
navigation; its current file also passed all seven tests independently.
